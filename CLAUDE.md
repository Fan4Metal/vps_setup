# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Обзор

Репозиторий состоит из одного bash-скрипта [vps_setup.sh](vps_setup.sh) — первичная настройка VPS на Ubuntu/Debian (запуск от root). Системы сборки, зависимостей и тестов нет.

## Команды

```bash
bash -n vps_setup.sh          # проверка синтаксиса
shellcheck vps_setup.sh       # линт (если установлен)

# Боевой запуск (из README, на самой VPS под root):
bash <(curl -s https://raw.githubusercontent.com/Fan4Metal/vps_setup/master/vps_setup.sh)

# Неинтерактивный прогон (все вопросы про SSH сняты переменными окружения):
HARDEN_SSH=1 SSH_CHANGE_PORT=0 bash vps_setup.sh
```

Скрипт изменяет систему целиком (apt, Docker, пользователи, sshd) — проверять его можно только на одноразовой VPS или в контейнере/VM, никогда на рабочей машине.

## Архитектура

Скрипт линейный и делится на четыре фазы; порядок фаз — существенная часть дизайна:

1. **Блок настраиваемых параметров** (верх файла): `DEFAULT_NEW_USER`, `DEFAULT_PUBLIC_KEYS` (массив), флаги SSH, `LOG_FILE`, цвета. Все флаги читаются из окружения через `${VAR:-}`.
2. **Функции** — `info/success/warn/error` (единственный способ печатать статус) и `ask_*` (валидация ввода в цикле: имя пользователя по regex, ключи по префиксу `ssh-rsa|ssh-ed25519|ssh-ecdsa` с отсевом дублей, порт 1–65535).
3. **Сбор ввода**: проверка root → `exec > >(tee -a "$LOG_FILE") 2>&1` → все вопросы → сводный баннер → финальное подтверждение. **Ни одно изменение системы не выполняется до подтверждения** — новые интерактивные вопросы добавлять только сюда, а не внутрь шагов.
4. **Пронумерованные шаги 1–8**: apt update/upgrade → вспомогательные пакеты → Docker → пользователь + `~/.bash_aliases` → группы sudo/docker → `authorized_keys` → `sudoers.d` → усиление SSH. Каждый шаг идемпотентен (проверки `id`, `command -v docker`, `grep -qxF` по ключу) — скрипт рассчитан на повторный запуск.

### Трёхзначная логика флагов SSH

`HARDEN_SSH`, `SSH_DISABLE_ROOT`, `SSH_DISABLE_PASSWORD`, `SSH_CHANGE_PORT`: пусто — спросить, `1` — включить, `0` — пропустить (`validate_flag` отвергает остальное). Флаг `HARDEN_SSH_FROM_ENV` различает два случая: `HARDEN_SSH=1` из окружения включает незаданные пункты молча, а ответ «да» в диалоге — заставляет спросить про каждый пункт отдельно. Если выбраны все три нуля, `HARDEN_SSH` сбрасывается в `0`.

### Защита от потери доступа (шаг 8)

Ключевая часть скрипта; при правках здесь сохранять все проверки:

- отказ отключать пароль, если `authorized_keys` пуст;
- настройки пишутся только в `/etc/ssh/sshd_config.d/01-custom-ssh-settings.conf`, в основной `sshd_config` при необходимости дописывается лишь строка `Include`;
- при активном `ufw` новый порт открывается **до** рестарта;
- `ssh.socket` (Ubuntu 22.10+) отключается, иначе `Port` игнорируется; имя сервиса определяется как `ssh` или `sshd`;
- `sshd -t` до `systemctl restart`, при ошибке — удаление своего конфига и выход;
- `visudo -cf` для `/etc/sudoers.d/$NEW_USER` (шаг 7) с удалением файла при ошибке.

## Соглашения

- Интерфейс, комментарии и сообщения коммитов — на русском; коммиты без трейлера соавторства.
- Окончания строк в `*.sh` — LF (задано в `.gitattributes`), файл запускается на Linux.
- `set -euo pipefail` — учитывать при добавлении команд, чей ненулевой код возврата нормален (`|| true`).
- При добавлении/удалении шага обновлять и его номер в `info "N. ..."`, и список пунктов в баннере.
